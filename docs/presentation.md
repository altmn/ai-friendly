# Repository presentation

The README helps a website owner understand the audit, inspect a useful example, get started, and recover from problems. Put evidence boundaries beside the task they qualify; put exhaustive architecture, catalog details, and historical verification in the existing reference/evidence documents.

Share task labels with the sibling skill repositories where applicable: Try it, Get started, Get help, Update or remove, Where it works, Technical details, Contribute. Keep AI-friendly's website questions and report examples distinct. Use semantic headings, descriptive links, selectable text, and readable prompts; content must remain understandable without color or images.

Provide AI-assisted prompts alongside direct instructions for setup, use, troubleshooting, and maintenance. Label the intended surface. Codex uses `$ai-friendly-audit` or its skill picker; ChatGPT uses actual `@` selection for available installed entries. This repository is a portable skill plus optional CLI, not a published ChatGPT plugin. A browser-help prompt should guide supported routes without claiming installation or tools the account does not have.

Download counters are optional **only when the displayed count is verifiably at least 100**. None is shown because a qualifying public metric has not been established. Before adding one, record its source, meaning, date/window, and value; display it conditionally or remove it if the displayed value falls below 100. Repository ZIP downloads, package downloads, and installations are distinct metrics.

## GitHub settings when publishing

Suggested About description: “Find out how well AI agents can find information and use your website, with evidence and prioritized fixes.” Retain the relevant website-audit, accessibility, frontend, agent-skills, and Codex topics. Use the README as the useful destination until a dedicated documentation site exists. Repository settings remain separate from this source change.
