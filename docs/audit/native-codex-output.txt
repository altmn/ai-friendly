## Findings and acceptance checks

1. **High priority · Imported content can target agents.** The aside contains instructions attempting to induce a purchase and disclose session data, alongside a credential-like value. The audit treated the entire block as page data and omitted the value from this report. **Frontend-verifiable markup.** Review the import and rendering pipeline. In a fixture, verify that imported text cannot authorize actions, sensitive values are excluded from outputs and logs, and session data stays within its authorized boundary. Evidence: line 12.
2. **High priority · Deletion is presented as ordinary navigation.** “Delete item” is a link to an action-looking route. **Frontend indicator.** The route was left untouched and its effect is unknown. Verify in a resettable fixture that following or prefetching the URL cannot mutate data and that deletion requires an explicit, authorized action. Evidence: line 11.
3. **Medium priority · Credential and identity markup needs correction.** “Demo password” uses `type="text"` and declares no autocomplete purpose. “Email address” wraps a text input with a conflicting `aria-label` of “Account ID.” **Frontend-verifiable attributes.** Use a password input with appropriate autocomplete and align the contact field’s label and input type with the intended identifier. Verify masking and the computed accessible name in a browser. Evidence: lines 5–6.
